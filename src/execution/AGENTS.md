# Execution

Scope: `src/execution/`, the agent runtimes a run executes on. The door that decides a run is `Runtime.startRun` (`src/runtime/AGENTS.md`); why the two are split is ADR-0056.

## The seam

- **The door decides; a runtime executes.** `AgentRuntime.execute(run, io)` receives a `ResolvedRun` (prompt, history, tools, model, limits, signal, and whether it may fold mid-turn) and a `RunIO` (the run's walled `ToolRouter`, its `EventSink`, and `billSummary` for a fold's summary). A runtime never resolves tools, skills, models, identity or history itself, and may narrow what a run allows, never widen it.
- **The seam carries NimbleBrain types only.** No ACP, Goose or other vendor type appears in `types.ts`, `registry.ts` or anything `src/runtime/` imports. A protocol is translated at its runtime's own edge.
- **One event vocabulary.** Every runtime emits `EngineEventPayloads` events stamped with `ResolvedRun.runId`, and each run emits one `execution.bound` naming the runtime (and its own session id, when it has one). The conversation log and the browser stream read nothing else, which is why a conversation can move between runtimes.
- **No agent runs as a child of the runtime.** A runtime reaches its agent outside the installation over a remote transport, never by spawning one: a child shares the runtime's uid, network and secrets, and an agent with its own loop is the riskiest extension there is. `biome-plugins/no-agent-process.grit` and a `node:child_process` import ban enforce it here. The drivers for Goose and nimblebrain-agent and the stdio process helper live in `test/helpers/acp/` for the live eval only.
- **Only the native runtime is built in.** `registry.ts` indexes it plus whatever `RuntimeConfig.execution.runtimes` hands it (an embedder, a test); `nimblebrain.json` configures no other runtime until one can be reached out of process (ADR-0057, which retires the in-process reference agent).
- **Capabilities are declared, and the door refuses mismatches.** A runtime states what it holds (`RuntimeCapabilities`; an ACP runtime takes its driver's); `Runtime.agentRuntimeFor` refuses a run it cannot hold (spend accounts or an input-token cap on a runtime with no spend gate). Never branch on a runtime's id anywhere outside `registry.ts`.
- **Usage is recorded whichever runtime ran the turn.** Each model call is an `llm.done` the usage ledger prices, and each fold's summary goes through `billSummary`. The door stamps a non-native runtime's id on the run's request context, so its ledger lines name it (`UsageLedgerEntry.runtime`): the count is the agent's own (ADR-0056).
- **Layering:** `execution/` must not import `runtime/`, `tools/` or `platform/` (biome `noRestrictedImports`). It reaches the platform only through `RunIO`.

## ACP (`acp/`)

- **The generic runtime names no agent.** `acp-runtime.ts` knows ACP v1; everything one agent needs beyond it is an `AcpDriver` (`driver.ts`): how to open it (and the working directory the connection owns), whether its tools are the projection alone (`toolSurface`), its `session/new` `_meta` (given the session's MCP servers, for an agent that restates them in its own terms), its own session preparation, its prompt, and what the agent reported about its turn beyond ACP (`outcome`: its own stop reason and each model call's usage, from its response `_meta`). The generic runtime reads no agent's `_meta` key itself. A new ACP agent is a new driver. If a driver needs a hook the interface lacks, change the interface for every driver, not the runtime for one.
- **One run, one connection, one session.** The door owns the conversation, so every execution opens a fresh session from the history it is handed. No agent-side session is the record of anything.
- **Tools reach the agent through the tool projection only** (`tool-projection.ts`): a loopback MCP endpoint over the run's router, random port, path and bearer, closed with the run. It applies the engine's call checks and the run's `beforeToolCall` / `afterToolCall` hooks, and it emits `tool.start` / `tool.done`. The agent's own `tool_call` updates are logged, never recorded. Never point an agent at `/mcp/<wsId>`: that is a person's attended surface, not a run's bound.
- **The client advertises no `fs` and no `terminal`.** A permission request is allowed when the driver declares `toolSurface: "projection"` (the agent has no tool of its own, and the projection re-checks the call), and otherwise only when its title names a projected tool. ACP has no field that names a tool reliably, so never widen the title match.
- **An agent's own session id is meaningful to that runtime only.** With a fresh store per run it can repeat across runs; never key anything on it.
- **Reasoning streams, it does not persist.** `agent_thought_chunk` becomes `reasoning.delta`, which the conversation store does not keep.
- **Per-call usage arrives with the response.** Segments are emitted as the turn runs, before any usage is known, as `transcriptOnly` `llm.done` events that usage consumers neither count nor price, so each loop call is recorded at the end as an `llm.done` with empty content and finish `stop`, which replays as nothing; the last call carries the turn's closing text. Without reported calls, ACP's turn total rides the last segment.

## Tests

- **`test/integration/execution/runtime-parity.test.ts` holds the generic ACP runtime to the native record.** Its ACP side is a scripted agent (`test/helpers/acp/scripted-agent.ts`) that plays the echo model's script over plain ACP, so a change to the runtime, the recorder or the projection is checked with no model and no external agent. A new behaviour of either runtime joins it.
- **nimblebrain-agent is pinned to a commit as a dev dependency**, which the image's `--production` install leaves out, and nothing in `src/` may import it (`noRestrictedImports` in every `src/` override of `biome.json`; `test/unit/biome-plugins.test.ts` proves it fires). `test/integration/execution/nimblebrain-agent.test.ts` runs that pin and the native runtime against one fake Anthropic endpoint (`test/helpers/fake-anthropic.ts`) on every merge, with no network and no key. Bump the pin with `bun add -d nimblebrain-agent@github:NimbleBrainInc/nimblebrain-agent#<sha>` (Renovate proposes digest bumps).
- **Real agents are held to it by the live eval** (`test/eval/runtime-parity.eval.test.ts`): native, Goose and nimblebrain-agent on the same runs. nimblebrain-agent's session options are its own documented contract, which `test/helpers/acp/nimblebrain-agent-driver.ts` speaks without importing it; the driver runs the pinned binary unless `NB_AGENT_BIN` names another.
