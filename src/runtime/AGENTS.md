# Runtime

Scope: `src/runtime/`. The run-start door is `Runtime.startRun`; why there is one door is ADR-0021.

## Run admission

Every unattended run is admitted at the door: `executeTask` holds one of the runtime's run slots for as long as the run executes (`src/runtime/admission.ts`, created by `Runtime.getRunAdmission`, sized by `runs.maxConcurrentRuns` / `maxQueuedRuns`). A source inherits it by calling `executeTask`; it never re-implements it (ADR-0045).

- **Chat is not admitted.** `startRun` itself takes no slot; only `executeTask` does. A person in the loop is not capacity the runtime schedules.
- **The door knows no sources.** A request names the run's `workspaceId` and, optionally, an opaque `key` the caller chose; a key already holding a slot or waiting is refused (`running` / `queued`). Never branch admission on what a key means. A source namespaces its keys so its withdrawals touch only its own runs.
- **A slot is a lease, released on every exit.** `executeTask` releases in a `finally`, including when the request is refused before the engine starts. `release` is idempotent, so a caller that handed in a lease releases it again on its own exit paths.
- **A caller that must answer at request time holds the slot itself.** `request(req, waiter)` says at once whether the run was admitted, queued (with its position in arrival order), or refused; the waiter's `admitted` / `withdrawn` callbacks run synchronously when the slot is granted or the entry leaves the queue. The caller passes the lease as `TaskRequest.admission`. A lease the pool does not hold is ignored and the run acquires its own, so a stray lease never bypasses the limit.
- **Without a waiter, a request never queues** (`busy`): for a caller whose place in line is durable elsewhere. A free slot with runs waiting is not offered to it, and `hasFreeSlot` is false while runs wait, which is how the run worker knows to leave its items on the work queue.
- **Fair share decides who takes a freed slot**: the waiting run whose workspace holds the fewest slots, the oldest among equals. A workspace alone in the queue takes every slot.
- **The queue is in memory.** `shutdown` stops admission after the sources are gone, refusing what nothing would drain.

## Spend accounts

Every run may name spend accounts (`RunBudget.spendAccounts`, `TaskRequest.spendAccounts`), checked at the door (`src/runtime/spend.ts`, held by `Runtime.getSpendBalances`). Each is an opaque id the source chose, a unit (`usd`, `input_tokens`, `output_tokens`), and the amount remaining (ADR-0045).

- **One live balance per id while any run naming it is in flight.** The first run to name an id sets its unit and balance; every later run naming it draws on that same balance. `startRun` holds the accounts for exactly as long as the engine runs and releases them in a `finally`; the last release discards the balance, and the source re-issues what is left (from the usage the run reported) on its next run.
- **The door never interprets an id.** Never branch on what an id means, parse it, or add a field naming a run's parent. Whether an id stands for a task, a batch, or a workspace is the source's knowledge (ADR-0021): the tasks plugin names its own in each work spec.
- **Each call is clamped and reserved before it is sent, debited after it.** The engine reaches the accounts only through `EngineConfig.spend` (a `SpendGate`). It projects the call's input as for `maxRunInputTokens` (the larger of the prompt estimate and the previous call's reported input) and asks for its output ceiling (the model's `maxOutputTokens`, plus an Anthropic `enabled` thinking budget, which the adapter adds on top). `check` answers with the largest output every account can pay for after the input, against each account's available balance (balance minus the reservations of calls in flight), and reserves the input plus that output; the engine sends the call with `maxOutputTokens` clamped to it. `debit` releases the reservation and subtracts the call's actual cost; a run ending (completed, aborted, or thrown) releases any reservation still outstanding. A call the run's cancel cuts off never gets reported usage, yet the provider bills it, so the engine debits it from estimates (the projected input, priced as a cache read up to what the run's previous call cached, and the output it streamed) and records it as a usage-only `llm.done` with `finishReasonRaw` `CUT_OFF_FINISH_RAW`.
- **When the run stops.** With stopReason `spend_limit` and `spendAccountId` naming the account, when an `input_tokens` account or a `usd` account cannot cover the projected input, or the output allowed falls below `MIN_SPEND_CALL_OUTPUT_TOKENS` (256, in `src/engine/engine.ts`) plus the thinking budget a call that small would add. The floor is low so that a budget below the model's ceiling still runs, its calls clamped, until almost nothing is left.
- **What the bound is.** Reservations against an account never sum past its balance, and a call cannot write more output than it reserved, so runs sharing an account exceed it only by input beyond the projection: when the prompt estimate undercounts, the debit takes the real amount and the balance goes negative by at most that excess, summed over the calls in flight. Pricing stays in the runtime: `usd` reserves input at the model's dearest input-side rate and output at the dearer of its output and reasoning rates, debits with `costBreakdown`, and an account on a model with no known rates lets no call through.
- **The model gateway's per-run budget stops a run the same way.** The gateway refuses a call past it with 429 and the body `rate limit exceeded` (`src/model/gateway-refusal.ts`), which no provider sends in that form. `modelGatewayFetch` throws it as `ModelBudgetSpentError` (not retryable) before the provider client reads it as a rate limit, and the run stops with `spend_limit` and `spendAccountId` `model-gateway:run`, an id the runtime holds no balance for. The ACP runtime does the same when an agent whose model access went to the gateway reports that answer. Trust the body only from the installation's gateway, and tell any other rate limit added to the gateway apart there, since it would answer the same way.
- **A run on a runtime held by the gateway's grant is reserved as a whole** (ADR-0063). Its calls never reach the door, so `openSpendAccounts` calls `SpendHold.reserveRun` instead of handing the engine a gate: each account reserves its balance divided by `sharedBy` (the most runs the source says may share it, a batch's concurrency; absent, one), capped at what is unreserved, and the least share in tokens (a `usd` share at the dearest per-token rate) and the run's input-token cap become the `grant` claim on its model credential. The runtime's reported `llm.done` usage is debited as it arrives, drawing the reservation down; `release` returns the rest. Only a runtime that mints a per-run credential, behind a gateway whose `/providers` answer says `"grants": true`, is held this way (`Runtime.holdsByGrant`). When the gateway stops such a run (`spendAccountId` `model-gateway:run`), the door names what set the grant instead: the account whose share it was, or stopReason `max_input_tokens` for the cap (`attributeGrantStop`), so a source tells its own account apart as for a native run. A cap stop keeps `spendAccountId` `model-gateway:run`, so a source says the gateway refused the run's next call, not that the engine projected it past the cap.
- **Chat names no account**, so it never opens a hold. Model calls outside the engine loop (title generation, mid-turn compaction) are not checked.

## The run worker

`src/runtime/run-worker.ts` runs what the bound tasks contract (`ai.nimblebrain.tasks`, `contracts/tasks/CONTRACT.md` §5) says is owed. The kernel binds it by contract id (`TASKS_CONTRACT`) and never names the plugin; with nothing bound there is no worker, nothing polls, and `tasks__*` does not exist. `Runtime.createTasksRunWorker` wires it; `start()` runs it last, `shutdown` stops it before the bound servers.

- **Due.** Per workspace served (every workspace at start, each one reached later through `ensureWorkspaceRegistry`, and on each interval), `due` is called as `host` every `DUE_INTERVAL_MS` and at once on the change hint, watched per workspace (`BoundServer.watch`). `until` is `now` plus a horizon longer than the interval, so `due` is always called again before `until` passes. Every page repeats the first page's `now` and `until`.
- **Enqueue.** Each occurrence is enqueued (kind `tasks.run`, scope the workspace, key the occurrence's, `notBefore` its own) with payload `{ workspaceId, ref }`. The queue's key is the dedupe: a repeat listing is one item. A future item is woken at its `notBefore`.
- **Claim only with a free slot.** The worker claims while `admission.hasFreeSlot()`, and takes the slot without a waiter in the turn the claim returns; a claim that finds no slot is let go (`retryAt` now). The slot rides `TaskRequest.admission` into `executeTask`. The lease is extended every `EXTEND_MS`; a lost claim stops the run (`interrupted`).
- **Begin.** `begin_run` with the claim's attempt and token. A skip delivers its notices; an `interrupted` earlier run is stopped if this process still runs it (it reports its own end), else ended with the host's `end_run` (error `interrupted`, usage and cost from the ledger, `ledgerUsageByRun`). The item settles only once that end is acknowledged; until then it is let go and claimed again, and the implementation names the run interrupted on every later claim until its end lands. An answer outside the document's closed schema is refused, never ignored: with a `runId` it ends `not_started`, `work_invalid`, under the same rule.
- **Run.** The grant is verified (`run-grant.ts`: signature, contract, workspace), and its owner must be a member now; the run acts as `{ id: owner }`, no org role. `exclusiveKey` is an in-process set per workspace, checked and taken in one synchronous step after the awaited membership check, so two runs never both pass it: correct because the filesystem queue serves one process (`multiProcess: false`); a multi-process queue needs the Leases provider for it. The door renders the work (`renderUnattendedPrompt`: notes and input in containment, the output-schema instruction), lowers its limits to `runs.*` (`effectiveRunLimits`), and enforces its spend accounts beside the host's own; an implementation's account only lowers what a run may spend. The worker's own timer ends a run at its `maxRunDurationMs`.
- **End.** The outcome is the contract's closed `run_outcome`, checked against the document before it is sent: stop reasons and errors mapped to its enums (cancel → `cancelled`, timeout → `timeout`, a lost claim → `error`/`interrupted`, shutdown → `error`/`internal` transient), tool calls by name, ok, `errorReason` and ms in call order (held and misnamed calls, which ran nothing, left out), files from the file store's own records (`TaskResult.filesWritten`, entries the run's id stamped; never a tool's output). `spendStop` is `reserved` when another run here holds the account and its balance is above zero, else `exhausted`. `end_run` is retried; one never acknowledged lets the item go, so the next claim closes the run as interrupted.
- **What a run holds stays held until its end is acknowledged.** The worker anchors a run's spend accounts (`SpendBalances.open`, a hold that never spends) and holds its exclusive key from before the run until its `end_run` lands, by run id rather than by claim: an end never acknowledged keeps them through the item's later claims until the interrupted close lands. So a run of the same account that starts in between draws on the live balance the first run spent. Dropping the workspace or stopping the worker releases them.
- **Notices** go to the workspace inbox under the source `tasks` (`deliverContractNotices`), one item per (source, notice id): the inbox's own dedupe, for its retention window. A run's end refreshes its owner's views (`announceIdentitySourceChange`).
- **Event triggers.** A notification route naming a task is offered with `offer_event` (`Runtime.offerTaskEvent`), as `host` walled to the route's author; accepted settles the route's row `delivered`, a refusal with the task's outcome. With no tasks plugin bound it answers `tasks_unavailable`.
- **Workspace delete.** `drop` stops serving the workspace and stops its runs before the teardown; after the archive rename `delete_workspace` purges its tasks (`purgeWorkspaceTasks`), as conversations does.

## The door's own model work

- **The door decides it; a runtime executes it, as for a turn.** A conversation's title and the between-turn history fold go through one narrow call (`Complete`, `src/history/completion.ts`): `Runtime.auxCompletion` gives the default runtime's when it brings its own model (`RuntimeCapabilities.ownModel`), else the slot's model. A runtime with its own model and access (a coding agent's CLI on a person's subscription) is the only thing that can spend that access, so the work runs there as an internal run (`src/runtime/aux-run.ts`): no tools, one iteration, no conversation, its usage billed as `aux.usage` under the model the agent reported. Never resolve a slot's model directly for new door-side work; take a `Complete` from `auxCompletion`.
- **An internal run is admitted and checked exactly as the native call it replaces**: no admission slot and no spend account, because it is work the door does for the turn that caused it. The mid-turn fold runs inside the native loop only, so it stays on the slot's model.
