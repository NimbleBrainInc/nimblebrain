# Automations

Scope: the automations platform app (`src/platform/automations/`). Tool-authoring rules for every platform app are in `src/platform/AGENTS.md`.

## Automations are workspace-owned

An automation lives at `workspaces/<wsId>/automations/<ownerId>/<automationId>.json`, one file per automation. Construct paths ONLY via `src/platform/automations/paths.ts` (`workspaceAutomationsDir` and friends); `check:automation-paths` rejects the identity-scoped `getIdentityContext(...).getDataPath("automations")` and hand-built `users/<id>/automations/` paths.

- **The workspace comes from `RequestContext.workspaceId`.** Like files, `automations__*` is an identity-door tool, so it reads the same single bound workspace every other kernel source does.
- **Every run fires as its owner.** Scheduled, Run now, and event runs build the same context: the automation's `workspaceId` and `{ id: ownerId }`, with no org role, so Run now tests the scheduled run with its authority, not the clicking person's. The scheduler scans `workspaces/*/automations/*/` and keys by `${wsId}/${ownerId}/${id}`. The run is an identity-bound session **walled to** the automation's provenance `workspaceId` — its tools plus the owner's identity tools, with NO cross-workspace reach.
- **Membership is re-checked per run.** It is stamped from the creator's trusted context at create, and the run-start door (`Runtime.startRun`) then denies any run whose owner is no longer a member of the provenance workspace (`WorkspaceMembershipRevokedError`, thrown before the opening message is written and before any tool binding). It is the same gate, at the same call site, that refuses a conversation resume — only the refusal differs, because the callers' contracts do. The scheduler classifies that denial as **skipped**, not failed: no `consecutiveErrors` bump, no auto-disable. So a removed owner's automation stops acting immediately and **self-heals** if they are re-added.
- **A run produces a run result, not a conversation.** Each run leaves a deliverable (final output), an activity log, and refs to any files it wrote (in the workspace file store) under `…/automations/<ownerId>/runs/<automationId>/` — an append-only `index.jsonl` of `AutomationRun` summaries plus a per-run `<runId>.result.json`. `runtime.executeTask` returns a `runId` and the deliverable, and creates no conversation.
- **An automation's `allowedTools` is enforced at the run's tool router, not only in surfacing.** For an unattended run, `IdentityToolRouter` drops tools outside the list from the run's reachable set, so `nb__manage_tools` cannot activate them, and refuses a call to one, so the list is a boundary rather than a display filter. `nb__search` reads `listDiscoverableTools`, not the router, so it can still list them. A chat's `allowedTools` stays a turn-start filter whose hidden tools remain promotable. Only `nb__search` and `nb__manage_tools` pass regardless, since finding and activating the listed tools is all a run needs; every other `nb__` tool must match the list, so an owner lists `nb__use_skill` for the skill catalog (a run without it gets none) and `nb__read_resource` for connector resources. The run's tool list is filtered by the same predicate (`isToolAllowedForRun`), so the model is never shown a tool the router refuses. An empty list means no narrowing, matching the form's "all"; the executor sends none.

## Run admission

Every run, whatever woke it, takes one of `Scheduler`'s global slots (`automations.maxConcurrentRuns`, default 2). Config is `src/config/automations.ts` (it lives in `config/` because `runtime/types.ts` may not import `platform/`).

- **Run now and event runs queue at the limit; scheduled runs defer.** `requestRunNow` and `runFromEvent` start a run when a slot is free and otherwise enqueue it (FIFO, bounded by `automations.maxQueuedRuns`, default 50; beyond it a skipped record). `dispatchRun` drains the queue in its `finally`, the moment a slot frees, so a queued run never waits for the timer and takes a freed slot ahead of a deferred scheduled run. A scheduled run never enters the queue: its persisted `nextRunAt` holds its place across restarts, which the in-memory queue cannot.
- **One run per automation.** A Run now or event run for an automation already in flight or queued is a skipped record. A refused Run now or event run does not move `nextRunAt`; only a skipped scheduled occurrence does.
- **The queue is in memory.** `stop()` records every queued run as skipped; a killed process loses them with no record. `cancelRun` removes a queued run and records it `cancelled`. `dropWorkspace` resolves the workspace's queued runs without writing.
- **Run now returns a ticket, not a promise of a run.** `RunNowTicket` says at once whether the run started, queued (with its position), or was refused, so `handleRun` can answer a queued run immediately with the `queued` envelope. `runNow` is the awaited form.
- **The token budget counts every run**, enabled or not, Run now included (`applyTokenBudget`). An enabled automation that spends its window is disabled; a disabled one is refused by Run now, as a skipped record, until the window resets (`runNowBudgetRefusal`, checked at request and again when it leaves the queue).
- **Per-run caps are clamped at execution, not at write.** `createDirectExecutor` sends every run `effectiveRunLimits`: the definition's `maxIterations` / `maxInputTokens` / `maxRunDurationMs` lowered to `automations.maxRun*`, with unset caps taking the runtime default held to the ceiling (and the input-token ceiling itself), so stored definitions written by any path are bounded. Create and update keep the value the caller set and report `effectiveLimits`, naming any cap that was lowered.
- **`NB_TIMEZONE` is validated once, in `createAutomationsSource`** (`resolveDefaultTimezone`): an unknown name falls back with a warning, because a throw while recording a run leaves it unrecorded and due.
