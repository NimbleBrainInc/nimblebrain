You can attach files to your messages to give the agent additional context. Drag a document into the chat, and the agent can read, summarize, or analyze its contents. The files plugin extracts text from common formats and NimbleBrain includes it in the conversation; images are passed straight to vision-capable models.

## How to attach files

Three ways to add files to a message in the web UI:

- **Drag and drop** — drag a file from your computer onto the chat input
- **Paste an image** — copy an image and paste it directly into the input (Cmd+V / Ctrl+V)
- **Click the attachment icon** — use the paperclip button next to the input to browse

Attached files appear as chips below the input. Remove a file by clicking the X on its chip before sending.

## Supported formats

| Format | Extensions | What the agent sees |
|--------|-----------|---------------------|
| PDF | `.pdf` | Extracted text, page by page, up to the text limit |
| Word | `.docx` | Document text and structure |
| Excel | `.xlsx` | Tabular data |
| Images | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp` | The image itself (visual analysis) |
| Plain text | `.txt`, `.md`, `.csv`, `.json`, `.xml` | File contents as-is |

## How it works

When you attach a file to a message:

1. Every file of the message is checked (count, size, type), then stored by the files plugin under your account, all or none
2. For a text, Word, Excel or other document, its text is read from the plugin, up to `maxExtractedTextSize` (200 KB by default)
3. That text is included as context in the conversation; an image or a PDF goes to the model as the file itself when the model takes it, and a PDF a model cannot take is read as text
4. The agent can reference the file content when responding

The plugin bounds its own extraction: a PDF is read until its text passes its limit (at most 2,000 pages or 5 seconds), and a Word or Excel file that would expand to far more is not extracted. It is still stored and attached, and the agent sees its name, type, and size.

Files **live in the workspace you upload them to**, under your own private partition — another member of that workspace can't see your files, and a file uploaded in one workspace isn't reachable from another. A `files://<id>` reference resolves within the workspace the conversation belongs to. Browse and organize them in the [Files app](/using/files/).

<Aside type="note">
  Images are sent directly to the model for visual analysis — the agent can describe what it sees, read text in screenshots, interpret charts, and more. This requires a vision-capable model (for example, Claude). Text-based formats are extracted and included as text alongside your message.
</Aside>

## Tips

- **Be specific about what you want.** Attaching a PDF and asking "Summarize the key financial metrics from Q3" gets a more focused answer than "Summarize this."
- **One file at a time works best** for detailed analysis. You can attach multiple files, but the agent handles focused requests better.
- **Screenshots work great** for asking about UI issues, error messages, or visual content.

## Turning files off

Files are served by the built-in files plugin, on by default. To turn files and attachments off:

```json title="nimblebrain.json"
{
  "plugins": {
    "files": false
  }
}
```
