---
title: Unattended Calls
description: The ai.nimblebrain/unattended key tells a server that a tools/call was fired by stored configuration, with no conversation and no person behind it.
---

| | |
|---|---|
| **Key** | `params._meta["ai.nimblebrain/unattended"]` on a `tools/call` request |
| **Value** | A short opaque string identifying the configuration that made the call |
| **Sent by** | The host only |
| **Fallback** | The server treats the call like any other |

## Why it exists

Most tool calls come from an agent working inside a conversation, with a person somewhere behind it. Some do not. A workspace can be set up so that the host calls a tool on its own when something happens. For example, a [notification route](/using/notification-channels/) can deliver an event by calling a server's tool. There is no conversation behind that call, no agent turn, and nobody to ask.

A server may want to respond differently to that call. It might skip a step that assumes someone will confirm, tag what it writes as automated, or apply a stricter policy. It can only do that if it knows which kind of call it received. MCP has no field for "who is asking", so the host says it here.

## Semantics

```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools/call",
  "params": {
    "name": "post_message",
    "arguments": { "channel": "ops", "text": "Deploy finished" },
    "_meta": { "ai.nimblebrain/unattended": "route:rt_01j9x2" }
  }
}
```

- **Present** means the host made this call from stored configuration, with no conversation.
- **Absent** means the call belongs to a conversation or to an automation run. Those calls have a conversation of their own, so they do not carry the key.
- **The value** identifies what made the call, for your logs. It is opaque: its format is not a contract, and the host decides nothing based on it. Do not parse it.

The key is a statement about the caller, and only the host can make it. The host never sends it on a result, and it removes the key from any result a server returns.

## Using it

Read the key, and do not require it. A server that ignores it behaves correctly. A server that reads it can narrow what it does for automated callers:

```python
@mcp.tool
async def post_message(channel: str, text: str, ctx: Context) -> dict:
    meta = ctx.request_context.meta
    automated = bool(meta and (meta.model_extra or {}).get("ai.nimblebrain/unattended"))
    return await send(channel, text, label="automated" if automated else None)
```

Use it to tighten behavior for automated calls, never to grant them more. The key tells you how the call was made, not who authorized it: authorization comes from the connection's credentials, as it does for every call.
