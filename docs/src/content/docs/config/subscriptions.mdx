A local NimbleBrain can run every turn on the coding agent you already pay for: Claude Code on a Claude Pro or Max subscription, or Codex on a ChatGPT plan. No model key is needed.

```bash
npx nimblebrain use claude    # or: use codex
```

Claude Code's turns run on **Sonnet** unless you name another model, because a chat turn on Sonnet answers faster than on Opus. Choose another with `--model`: an alias (`sonnet`, `opus`, `haiku`) or a full model id, which the worker passes to `claude --model` as it is. Codex runs on its own default model unless you name one your plan offers.

```bash
npx nimblebrain use claude --model opus
```

`npx nimblebrain` offers it when it asks what runs NimbleBrain's agents, and marks it when Claude Code or Codex is already signed in. `use api` or `use local` moves back to an API key or a local model ([What runs the agents](/cli/nimblebrain/#what-runs-the-agents)). It needs macOS with Docker Desktop and NimbleBrain v0.87.0 or newer (v0.87.1 for quick titles and summaries on Haiku); `npx nimblebrain update` moves an install to the newest release.

<Aside type="caution" title="Experimental, and local only">
This is for one person's NimbleBrain on their own machine: the runtime accepts it only under the `dev` adapter in [`instance.json`](/config/instance-json/). A subscription is yours, so it never backs an instance other people sign in to.
</Aside>

## How it works

`use claude` or `use codex` starts a small worker on your machine, on `127.0.0.1`. For each turn, NimbleBrain hands the turn to the worker over the [Agent Client Protocol](https://agentclientprotocol.com), and the worker runs the vendor's own CLI, unmodified and signed in as you:

- **Claude Code** runs `claude -p` with none of its built-in tools, none of your settings, hooks, plugins or `CLAUDE.md`, and only one MCP server: your NimbleBrain workspace.
- **Codex** runs `codex exec`, ignoring your `config.toml`, with your NimbleBrain workspace as its only MCP server. It keeps a read-only shell, which Codex cannot turn off; each command it runs shows in the turn.

Your workspace's tools reach the CLI through the worker: each turn gets a private loopback address, and every tool call the CLI makes there goes back to NimbleBrain over the turn's own connection, through the same workspace wall and permission checks as any other turn. The worker never sees or holds your login: the CLI reads its own sign-in.

## Billed to your subscription, never an API key

The worker checks this, rather than assuming it:

- It removes every API key variable (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` and the like) from the CLI's environment, because Claude Code would otherwise prefer a key it finds there.
- It refuses to start unless `claude auth status` reports a claude.ai subscription, or `codex login status` reports Sign in with ChatGPT. `use` names the command to fix it: `claude /login`, or `codex logout` and then `codex login`.
- It stops a Claude turn at once if Claude Code reports any API key as its source.

Usage still counts against your plan's own limits, and NimbleBrain records each turn's tokens under `claude-code-subscription:<model>` or `codex-subscription:codex`, at $0, since your subscription pays for them.

## What runs where

| | On your subscription | Needs a model key |
|---|---|---|
| Chat turns, and scheduled tasks without a spend budget | Yes | — |
| The conversation's title, and the summary that folds a long history | Yes: on the same agent, with no tools attached, and on Claude Code on Haiku, so each takes a couple of seconds | — |
| A run with a spend budget (a budgeted task or batch) | — | Yes: it runs on NimbleBrain's own engine, which can hold it to the budget |

The chat composer shows what every turn runs on in place of the model picker, such as **Claude Code (Sonnet) · Claude Max** or **Codex · ChatGPT**: the model is the one `use` chose, so a model chosen in the composer would not be used. Change it with `npx nimblebrain use claude --model <model>`. When the worker does not answer, it says **Claude Code isn't running**, with the fix on hover.

## When a turn fails

A turn on a worker that is not running fails with "Claude Code isn't answering. Start it on this machine with `npx nimblebrain up`, then send your message again." (`agent_unreachable`). When the worker answers but the CLI cannot finish the turn, the chat shows why, in words that name the fix:

| Chat error | Means | Fix |
|---|---|---|
| `agent_signed_out` | Claude Code's or Codex's sign-in expired or is gone. The chat offers no retry, since a retry fails the same way. | Run `claude /login`, or `codex login` and choose Sign in with ChatGPT, in a terminal, then send the message again. |
| `agent_plan_limit` | Your plan's usage limit is reached. The message says when it resets when the CLI says so. | Send it again once it resets, or move to an API key with `npx nimblebrain use api`. |
| `agent_api_key` | Claude Code reported an API key as its source, so the turn was stopped before it billed one. | Remove that key from the environment Claude Code reads, or run `claude /login`. |
| `agent_cli_missing` | The worker could not find `claude` or `codex`. | Install it, sign in, then run `npx nimblebrain use claude` (or `codex`) again. |
| `agent_cli_failed` | The CLI stopped for another reason. The message gives its last line, without any credential. | Read `agent-worker.log` in the install's folder, then send the message again. |

## When a turn is slow

When a turn has shown nothing for 15 seconds, the chat shows a waiting line in the agent's thinking, such as "Waiting for Claude Code to start answering (15s)…", and again every 15 seconds until the first text, thinking or tool call. When the CLI reports that it is retrying the model request, the line says so: "Claude Code is retrying the API request (attempt 2 of 10, 30s so far)…". The line is not saved with the conversation. A title or summary the worker makes in the background shows none.

Each turn also leaves one line in `agent-worker.log` in the install's folder, when it ends:

```text
[19:46:05] timeline turn claude-code sonnet: spawn 0.0 init 0.3 request 0.3 message_start 38.9 first_thinking - first_text 39.0 first_tool - result 39.5 exit 39.6 | events: 12.1 retry 1/10 overloaded 529 next in 0.6s | rate_limit: allowed seven_day 0.27
```

- The numbers are seconds since the worker started the CLI. `-` is a point the turn never reached.
- Claude Code: `init` is its first line, `request` when it sent the model request, `message_start` when the model's answer began, then the first thinking, text and tool call, the result, and the process's exit. A long gap between `request` and `message_start` is time spent waiting on the model service, not on NimbleBrain or the worker.
- Codex: `thread` and `turn` (its `thread.started` and `turn.started`), the first item, the first reasoning, message and tool call, the result, and the exit.
- `events` lists each retry with its attempt, the error Claude Code names (`overloaded`, `rate_limit`, `server_error`, …) with its HTTP status, and `no_response` when no response came within Claude Code's first-byte window; for Codex, each `Reconnecting… n/m` with its reason, and any other error or notice.
- `rate_limit` is the plan window Claude Code last reported: its status, which window, and how much of it is used. Codex reports none.
- `turn` is a chat turn; `internal` is a title or summary, which runs on Haiku for Claude Code.

The line never holds your prompt, the answer, tool calls' arguments or output, or a credential.

## After a reboot

`use` installs the worker as a login item: a LaunchAgent for your user only, `~/Library/LaunchAgents/ai.nimblebrain.agent-worker.<project>.plist`, running a copy of the CLI kept in the install's folder. launchd starts the worker when you log in, as Docker Desktop starts NimbleBrain, and starts it again within half a minute if it crashes. `down` removes the item, since Docker does not start a stopped NimbleBrain at login either, and `up` puts it back; `use api`, `use local` and `uninstall` remove it too.

## Limits

- macOS with Docker Desktop only for now. On Linux the container reaches the host over the Docker bridge, not `127.0.0.1`, and `use` answers `HOST_LOOPBACK_UNREACHABLE`. Anywhere else `use` answers `PLATFORM_UNSUPPORTED`: the worker runs as a launchd login item.
- A Codex turn carries Codex's own instructions and tool schemas, roughly 100k input tokens even for a short turn, most of them cached.
- The worker holds each turn's connection. A turn running when it stops (a crash, `down`, `use api`) is cut off, as when NimbleBrain itself restarts.
- Codex's MCP client speaks an older protocol revision than `/mcp/<workspaceId>` serves, so connecting Codex to NimbleBrain as a tool (`init --agent codex`) gives it no tools. Running NimbleBrain's turns on Codex, as here, is not affected: the worker serves the tools to Codex itself.
