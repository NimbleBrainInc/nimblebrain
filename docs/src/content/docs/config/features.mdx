Feature flags control which system capabilities are available. All seven flags default to `true`. Setting a tool-gated flag to `false` removes the capability entirely — the tool is not registered, not visible to the LLM, and is rejected if a client calls it directly. `compaction` gates engine behavior rather than a tool: setting it to `false` disables history compaction.

## Configuration

Add a `features` object to your `nimblebrain.json`:

```json title="nimblebrain.json"
{
  "features": {
    "skillManagement": true,
    "toolDiscovery": true,
    "connectorDiscovery": true,
    "fileContext": true,
    "userManagement": true,
    "workspaceManagement": true,
    "compaction": true
  }
}
```

You only need to include flags you want to change. Omitted flags use their default (`true`).

## Flag reference

| Flag | Default | Controls | Tool(s) gated |
|------|---------|----------|---------------|
| `skillManagement` | `true` | Create, edit, delete, and activate user skills | `skills__create`, `skills__update`, `skills__delete`, `skills__activate`, `skills__deactivate`, `skills__history`, `skills__restore`, `skills__set_status` |
| `toolDiscovery` | `true` | Search installed tools by keyword | `nb__search` (`scope: "tools"`) |
| `connectorDiscovery` | `true` | The registry scope of `nb__search` (not the catalog itself — `manage_connectors` reads it ungated) | `nb__search` (`scope: "registry"`) |
| `fileContext` | `true` | File upload and context extraction | File processing pipeline |
| `userManagement` | `true` | Create, update, and delete users | `nb__manage_users` |
| `workspaceManagement` | `true` | CRUD workspaces and manage members | `nb__manage_workspaces` |
| `compaction` | `true` | History compaction — fold the oldest turns of a long conversation into a summary at run start to bound context growth. User-authored messages (instructions, corrections) are retained verbatim across compaction, bounded. Event-sourced stores only. | — (engine behavior, not a tool) |

<Aside type="note">
  Connector install and configuration are not feature-gated. They happen through the connectors catalog (`manage_connectors`) and the CLI, and are governed by workspace admin rights rather than a flag.
</Aside>

## Always-enabled tools

Tools not listed in the table above are never gated by feature flags. They register and stay visible regardless of feature configuration — for example `nb__status`, `nb__search` itself (only its `scope`-specific behavior is gated), and the read-only platform tool surfaces.

## Enforcement

Feature flags are enforced at tool registration. A gated tool whose flag is `false` is excluded at startup — it never appears in `tools/list` for the LLM, the web shell, or external MCP clients, and a direct call to it is rejected. `compaction` is enforced differently: it changes engine behavior at run start rather than gating a tool.

<Aside type="tip">
Use feature flags to narrow a deployment's tool surface — for example, disable `skillManagement` to stop the agent mutating skills. Treat them as tool-surface configuration, not as a security boundary: `connectorDiscovery` withholds `nb__search`'s registry scope, but `manage_connectors` reads the same catalog and is not feature-gated, so turning the flag off narrows how the agent reaches the registry rather than whether it can.
</Aside>
