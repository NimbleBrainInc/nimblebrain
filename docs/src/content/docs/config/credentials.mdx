Every connector is a remote MCP server, so every credential is a credential for
reaching one. NimbleBrain never holds a connector's own secrets on its behalf:
it holds what it needs to authenticate the connection, workspace by workspace.

## The three shapes

### OAuth tokens (the common case)

A connector installed from the catalog authenticates over OAuth. The tokens the
flow produces are workspace-scoped and land at
`{workDir}/workspaces/{wsId}/credentials/mcp-oauth/{serverName}/` with `0o600`
permissions under a `0o700` directory. Connecting a service in one workspace
never exposes it to another; disconnecting invalidates that workspace's tokens
and nothing else.

A **personal connector** is the same flow bound to your identity instead of a
workspace — its tokens live under `users/{userId}/credentials/` and follow you
across workspaces. See [Personal connectors](/using/personal-connectors/).

### An operator's OAuth client (static auth)

Vendors that don't support Dynamic Client Registration (Gmail, Outlook, HubSpot,
Asana, …) need an OAuth app the operator registers in the vendor's developer
portal. The workspace admin enters the `client_id` and `client_secret` on the
connector's **Configure** page. The id is public and sits in `workspace.json`;
the secret goes to the workspace credential store and is resolved per request,
so it never appears in the workspace record or in any API response.

Until that pair is configured, the connector reads as **needs setup** and the
Connect button is replaced by **Set up OAuth**.

### A brokered connection

A connector fronted by a gateway (Composio, Smithery) holds its upstream grant
at the broker. NimbleBrain stores only an opaque pointer to that connection —
never the vendor key. The platform-wide gateway API key stays in the platform
environment. See [Connector Providers](/config/connector-providers/).

<Aside type="note">
  There is no host-side credential injection: the runtime does not download,
  unpack, or spawn a server, so there is no subprocess environment to put a
  secret into. A server that needs its own API key holds it on its own side.
</Aside>
