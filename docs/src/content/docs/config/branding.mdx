The `brand` block in `nimblebrain.json` white-labels a deployment: your users see your product name, your logos, your accent colour and your typefaces in place of NimbleBrain's. Every key is optional. Without a `brand` block the deployment is NimbleBrain, unchanged.

`brand` is a top-level key of `nimblebrain.json`, not a preference, and it is not read from `nimblebrain.overrides.json`. Changing it needs a restart.

## What it changes

| Surface | Reads |
|---|---|
| The agent's identity line ("You are a helpful assistant powered by …") | `name` |
| OAuth consent screens at connector vendors (dynamic client registration) | `name`, `homepageUrl`, `logo.raster` |
| The OAuth "You're in." success page and the OAuth error pages | `name`, `colors` |
| Connector-tool error messages | `name` |
| `GET /v1/brand.js`, which the web client loads before its bundle | the whole block |

Wire identifiers do not change: MCP client and server names, the `nb__` tool namespace, `ai.nimblebrain/*` metadata keys, the `NB_` environment prefix, the `nimblebrain.json` filename. They identify the software to other software, not to a person.

## Keys

| Key | Type | Description |
|---|---|---|
| `name` | `string` | Product name shown wherever a person reads "NimbleBrain". 1–64 characters, no `<`, `>`, `{`, `}`. Default: `"NimbleBrain"`. |
| `homepageUrl` | `string` | Your homepage. Sent as `client_uri` when registering OAuth clients. |
| `logo.light` | `string` | Full logo for light mode. |
| `logo.dark` | `string` | Full logo for dark mode. |
| `logo.mark` | `string` | Square mark, for places the full logo does not fit. |
| `logo.raster` | `string` | PNG mark, sent as `logo_uri` when registering OAuth clients. A raster because several identity providers refuse to render SVG there. |
| `favicon` | `string` | Favicon URL. |
| `defaultTheme` | `"light"` \| `"dark"` \| `"system"` | The colour theme a person starts in until they choose one. `"system"` follows their operating system. A person's own choice always wins. Default: `"system"`. |
| `colors` | `object` | The accent (`primary`) and focus ring (`ring`). See [Colours](#colours). |
| `fonts` | `object` | Typeface overrides for the `sans`, `heading` and `reading` roles. See [Fonts](#fonts). |

Every URL is absolute (`http://` or `https://`) and must resolve. A set URL that returns 404 renders a broken image, not the default artwork, so publish assets before you reference them.

When `name` is set, OAuth registration sends only your values: without a `homepageUrl` no `client_uri` is sent, and without a `logo.raster` no `logo_uri` is sent. NimbleBrain's are never sent on your behalf.

## Colours

`colors` sets two tokens, each a `[light, dark]` pair of `#rrggbb` hex colours, the same shape the palette itself uses:

| Token | Paints |
|---|---|
| `primary` | The accent: primary buttons, links, accent text. |
| `ring` | The focus ring. Usually the same value as `primary`. |

The text on a `primary` fill is not set: it is derived per mode as white or black, whichever has the higher contrast against your `primary`. Every other colour stays canonical.

### The contrast rule

The runtime merges your colours over the canonical palette at startup and checks the result against every contrast pair the canonical palette is held to, in both modes: the derived text on your `primary` fill, accent text on the page and on cards, the accent's hover fill, and the rest. Every pair must clear **4.5:1**, the WCAG 2.2 AA minimum for body text.

A brand that fails any pair stops the runtime at startup with an error naming the pair, the mode, the two colours and the ratio:

```text
Invalid brand in config: light mode: primary on background (links, accent text) is 1.61:1 (#CCCCCC on #ffffff), below the 4.5:1 WCAG AA minimum
```

A `primary` that fails is too light for light mode or too dark for dark mode. Darken the light value, or lighten the dark one, until it passes.

## Fonts

Each role takes a CSS `stack` (required) and, optionally, one file to load:

| Key | Description |
|---|---|
| `stack` | The CSS `font-family` value, fallbacks included: `"'Instrument Sans', system-ui, sans-serif"`. |
| `family` | The family name the file is declared under — the name `stack` refers to it by. Required with `url`. |
| `url` | One woff2 file, typically a variable font covering every weight you use. |
| `weight` | The `font-weight` that file covers: `"400"`, or a variable range `"400 700"`. Only with `url`. |

The roles are `sans` (interface text), `heading` and `reading` (the agent's prose in chat). Code keeps the canonical monospace face.

**A font URL is a `.woff2` file, never a stylesheet.** Google Fonts CSS URLs (`https://fonts.googleapis.com/css2?…`) are rejected. Embedded apps load faces from the file URL directly, so a stylesheet that points at files cannot reach them. Self-host the woff2 files, and make sure their license allows redistribution.

**The server hosting the font files must send `Access-Control-Allow-Origin: *`.** Browsers fetch fonts in CORS mode, and an embedded app runs in an opaque origin, so its requests arrive with `Origin: null` and no narrower value matches them. Without the header the shell may still render the font while apps silently fall back to the next family in `stack`.

**A role with no `url` must name a font your users already have** — a system font such as `Georgia`. Nothing is downloaded for it.

## Example

A complete block for a fictional ACME deployment:

```json title="nimblebrain.json"
{
  "brand": {
    "name": "ACME",
    "homepageUrl": "https://acme.example",
    "logo": {
      "light": "https://static.example.com/brands/acme/logo-light.svg",
      "dark": "https://static.example.com/brands/acme/logo-dark.svg",
      "mark": "https://static.example.com/brands/acme/mark.svg",
      "raster": "https://static.example.com/brands/acme/mark-128.png"
    },
    "favicon": "https://static.example.com/brands/acme/favicon.png",
    "defaultTheme": "light",
    "colors": {
      "primary": ["#B53707", "#FF8A4C"],
      "ring": ["#B53707", "#FF8A4C"]
    },
    "fonts": {
      "heading": {
        "stack": "'Syne', system-ui, sans-serif",
        "family": "Syne",
        "url": "https://static.example.com/brands/acme/fonts/syne-latin-wght-normal.woff2",
        "weight": "400 800"
      },
      "sans": {
        "stack": "'Instrument Sans', system-ui, sans-serif",
        "family": "Instrument Sans",
        "url": "https://static.example.com/brands/acme/fonts/instrument-sans-latin-wght-normal.woff2",
        "weight": "400 700"
      },
      "reading": {
        "stack": "'Fraunces', Georgia, serif",
        "family": "Fraunces",
        "url": "https://static.example.com/brands/acme/fonts/fraunces-latin-wght-normal.woff2",
        "weight": "300 700"
      }
    }
  }
}
```

## `GET /v1/brand.js`

The runtime serves the validated block as a script at `GET /v1/brand.js`, unauthenticated, with `Content-Type: text/javascript` and `Cache-Control: public, max-age=60`. The body is one assignment:

```js
window.__NB_BRAND__ = {"name":"ACME","defaultTheme":"light"};
```

The web client loads it with a plain `<script>` before its bundle, so the brand is in place before the first paint. It is public because the sign-in page shows the brand before anyone has signed in, and nothing in it is private. Without a `brand` block it assigns `{}`.

The served block is the configured one, holding only the keys on this page. A key the schema does not define is reported as an unknown key at startup and ignored; it is never served.

The web client applies the brand before its first render and keeps the last answer in the browser, so a returning visitor sees the brand at once and a change reaches them on the next page load after the cache expires. Removing the `brand` block restores the default look the same way.

## Changes and OAuth consent screens

<Aside type="caution">
Connector vendors keep the name, homepage and logo they received when a connection first registered its OAuth client. After setting or changing `brand`, an existing connection keeps showing the old values on the vendor's consent screen until it is disconnected and connected again. New connections register with the new values.
</Aside>
