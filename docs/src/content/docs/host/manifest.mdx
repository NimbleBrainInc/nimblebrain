NimbleBrain reads host metadata from the `_meta["ai.nimblebrain/host"]` key on your server's catalog entry — the upstream MCP registry [`ServerDetail`](https://github.com/modelcontextprotocol/registry) record an operator adds to the [connectors catalog](/config/connectors-catalog/). `ai.nimblebrain/host` is one block with several fields, each a grant the operator reviews ([Host integration](/host/overview/)). This page gives the shape of each field; the page linked from each row says what the host does with it. The counts your app shows on the workspace overview are not declared here: your server reports them over MCP with the [facets extension](/extensions/facets/).

The block has a published JSON Schema at
[`schemas.nimblebrain.ai/host/v1/host.schema.json`](https://schemas.nimblebrain.ai/host/v1/host.schema.json)
— point your editor's `$schema` at it for completion and validation while authoring.

<Aside type="note">
  The runtime reads this block from the catalog entry, not from a package it
  downloads: it connects to remote MCP servers and never acquires or executes a
  server's code. If you also ship an [MCPB](https://github.com/modelcontextprotocol/mcpb)
  `manifest.json` for other hosts, keep the same `_meta` block there — it is the
  same extension, read from wherever that host reads its metadata.
</Aside>

## Full catalog entry

```yaml title="catalog/my-app.yaml"
servers:
  - name: com.myorg/my-app
    title: My App
    description: My NimbleBrain app
    version: "1.0.0"
    remotes:
      - type: streamable-http
        url: https://my-app.myorg.com/mcp
    _meta:
      ai.nimblebrain/host:
        hostVersion: "1.0"
        placements:
          - slot: sidebar.apps
            resourceUri: ui://dashboard
            priority: 50
            label: My App
            route: my-app
          - slot: settings
            resourceUri: ui://settings
```

## Host metadata: `_meta["ai.nimblebrain/host"]`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `hostVersion` | `string` | Yes | Contract major version. Write `"1.0"`. It changes only on a breaking change: every field in this table is part of `1.0`, and a block is turned on by declaring it, not by the version. The host accepts any `1.x` and skips a catalog connector that declares another major. |
| `placements` | `PlacementDeclaration[]` | No | Shell layout placement declarations: sidebar items, main views, and the settings section. Shape [below](#placementdeclaration); behavior in [Placements & navigation](/host/placements/) and [Settings sections](/host/settings-sections/). |
| `hooks` | `HookDeclaration[]` | No | Inbound event streams your server accepts from a vendor over plain HTTPS, one entry per vendor: `{ vendor, route, registerTool, description?, headerRenames? }`. Read from a catalog entry only. A `route` may not be your MCP endpoint's path or a path under it. See [Inbound webhooks](/host/webhooks/). |
| `notifications` | `object` | No | The outbox your server exposes, one resource the host polls for facts nobody asked for: `{ resource, description? }`. See [Notifications](/host/notifications/). |
| `adminTools` | `string[]` | No | Names of tools on your server that only a workspace admin may call, at most 64. Read from a catalog entry only. See [Admin-only tools](/host/admin-tools/). |
| `recordArguments` | `boolean` | No | `true` grants your server record arguments in every workspace that installs it: the host reads the resources your tools' declared arguments name, from the servers in the workspace that serve them. Without it the host reads none. A workspace admin can narrow or revoke it. Read from a catalog entry only. See [The grant](/extensions/resource-arguments/#the-grant). |

<Aside type="note" title="A server added by URL on a local install">
  On a local install (`npx nimblebrain`), a server in development can be added
  by its loopback URL instead of a catalog entry. The runtime then reads the
  server's MCP Server Card (SEP-2127) at `<url>/server-card` and takes its `title`, `description`, `icons`, and,
  from this block, `placements` only. `hooks`, `notifications`, `adminTools`
  and `recordArguments` are grants an operator makes in a catalog entry, and a
  card's are ignored. A card icon may be `https:`, a `data:` image, or a loopback
  `http:` URL. Without a card the server is added with no placements. A Python server built on `nimblebrain-server-sdk` serves its card with
  [`add_server_card`](/server-sdk/server-card/).
</Aside>

The block has no `name`, `icon`, `category`, `primaryView` or `briefing`, and a placement has no `size`; a block that still declares them loads, and the host ignores them like any unknown key. A connector's display name is its catalog entry's `title` (or `name`), and its icon the entry's `icons`, the fields the MCP Registry `ServerDetail` already defines. A sidebar entry's label is its placement's own `label`.

### Spelling

Every field is camelCase, and camelCase is the only spelling the host reads. A
snake_case key (`host_version`, `record_arguments`, a hook's `register_tool` or
`header_renames`) is read as absent: a block with only `host_version` has no
version, so the entry is dropped, and a hook with only `register_tool` is
dropped. One key is the exception: a block that contains `admin_tools`, with any
value and whether or not `adminTools` is beside it, gates every tool on the
server, so a catalog still written in the old spelling can never open admin-only
tools to every member. That holds when the entry is dropped too: it leaves
Browse, and a connector already installed from it keeps every tool admin-only.
The host logs a warning naming the key.

### `PlacementDeclaration`

Each entry in the `placements` array:

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `slot` | `string` | Yes | — | Shell slot to fill: `"sidebar.apps"` (or any `"sidebar.<group>"`), `"sidebar"`, `"sidebar.bottom"`, `"main"`, or `"settings"`. See [Placements](/host/placements/). |
| `resourceUri` | `string` | Yes | — | `ui://` URI served by this MCP server. |
| `priority` | `number` | No | `100` | Sort order within the slot. Lower values appear first. |
| `label` | `string` | No | — | Human-readable label for sidebar items. Ignored for `"settings"`. |
| `icon` | `string` | No | — | Lucide icon name (kebab-case), shown on a `sidebar.bottom` entry. Falls back to `CircleDot` if unset or unrecognized. A connector's other sidebar entries show its catalog `icons`. |
| `route` | `string` | No | — | Route path. Registers as `/w/<slug>/app/<route>`. Ignored for `"settings"`. |

## Minimal example (UI app)

The smallest catalog entry that registers a UI view:

```yaml title="catalog/hello.yaml"
servers:
  - name: com.myorg/hello
    title: Hello
    description: Says hello
    version: "0.1.0"
    remotes:
      - type: streamable-http
        url: https://hello.myorg.com/mcp
    _meta:
      ai.nimblebrain/host:
        hostVersion: "1.0"
        placements:
          - slot: sidebar.apps
            resourceUri: ui://index
            route: hello
            label: Hello
```

## Minimal example (tools only)

No `_meta` needed for a tools-only server:

```yaml title="catalog/calculator.yaml"
servers:
  - name: com.myorg/calculator
    description: Arithmetic
    version: "1.0.0"
    remotes:
      - type: streamable-http
        url: https://calculator.myorg.com/mcp
```
