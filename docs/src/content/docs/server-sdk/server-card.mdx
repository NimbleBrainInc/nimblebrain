An MCP Server Card ([SEP-2127](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2127), extension `io.modelcontextprotocol/server-card`) is a JSON document that names and describes one server. A server on streamable HTTP serves it at `GET <streamable-http-url>/server-card` with the media type `application/mcp-server-card+json`: a server at `http://127.0.0.1:8000/mcp` serves it at `/mcp/server-card`. A client reads it before it connects.

When you add a server to a local NimbleBrain by its URL, NimbleBrain reads its card. The card's `title`, `description` and first icon name the connector, and the `placements` in its `ai.nimblebrain/host` block put the server's views in the sidebar, with no catalog entry. Without a card the server still connects, named by its `serverInfo` and with no placements.

## What the card carries

| Field | From |
|---|---|
| `name` | The server's name, `FastMCP("com.example/notes")`. The card requires reverse-DNS form with one slash. |
| `version` | `FastMCP(version=...)`. Unset, FastMCP reports its own version, so set it. |
| `description` | `add_server_card(description=...)`, 1 to 100 characters, for a person choosing the server. Not the `instructions`, which are for the model. |
| `title` | `add_server_card(title=...)`, 1 to 100 characters. Omitted when not given. It is also the handshake's `serverInfo.title`. |
| `websiteUrl`, `icons` | `FastMCP(website_url=..., icons=...)`. NimbleBrain shows the first icon that is `https:`, a `data:image/...` URI, or `http:` on a loopback host. |
| `_meta["ai.nimblebrain/host"]` | `add_server_card(placements=[...])`, as `{"hostVersion": "1.0", "placements": [...]}`. Each placement has the keys of a [catalog entry's placement](/host/manifest/#placementdeclaration). Omitted when there are none. |

`name`, `version`, `websiteUrl` and `icons` are the values the server's `serverInfo` reports, so the card cannot contradict the live connection. FastMCP has no place for a title or a description, so you declare them, once, in `add_server_card`.

## The title in the handshake

`add_server_card` also reports the `title` as the server's `serverInfo.title`: in the `initialize` result on 2025-11-25, and in the `serverInfo` stamp of the `server/discover` result on 2026-07-28. A client that reads only the live connection then shows the title, not the reverse-DNS name. If the server already reports a title there through its own middleware, that title is kept. The `serverInfo` stamp on other 2026-07-28 results carries no title, since a FastMCP middleware cannot reach it.

## The rules

- **Refused at import:** a name that is not reverse-DNS, an empty or over-long description or title, a version range, a placement whose `resourceUri` is not `ui://<authority>/<path>`, placements under two authorities, an unknown placement key, and a second card on one server. The name, version, description and title limits are the Server Card schema's, so a reader that validates against it refuses such a card; NimbleBrain drops the placement ones.
- **Streamable HTTP only.** The card follows the MCP path (`mcp.http_app(path="/api/mcp")` serves `/api/mcp/server-card`). Over stdio, or on the SSE transport, nothing is served.
- **Public and read-only.** `GET` only, with no authentication even when the server has an auth provider, CORS open to any origin, `Cache-Control: public, max-age=3600`, and an `ETag` that `If-None-Match` revalidates. FastMCP's host and origin checks still apply to a server bound to a loopback address.
- **No `remotes`.** A server cannot reliably know the URL its clients reach it at (it binds `0.0.0.0`, sits behind a proxy, or is reached through a container's host alias), and a client that fetched the card already has it.
- **Advisory.** A host prefers what the live connection reports, and nothing in a card decides access. On a card NimbleBrain reads only the `placements` of the host block; hooks, notifications, admin tools and record arguments are grants an operator makes in a catalog entry.
