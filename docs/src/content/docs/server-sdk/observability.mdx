## Metrics

`GET /metrics` serves Prometheus text. When `METRICS_PORT` is set, the registry is also served on that metrics-only port, so a scraper never needs to reach the port that serves `/mcp`.

| Metric | Labels |
|---|---|
| `http_requests_total` | `method`, `route`, `status` |
| `http_request_duration_seconds` | `method`, `route` |
| `http_in_flight_requests` | `method` |
| `service_errors_total` | `service`, `code`, `upstream_status` |

- `route` is the route template, never the raw path.
- `service_errors_total` counts every error [surfaced through the error contract](/server-sdk/errors/).
- `counter`, `gauge` and `histogram` declare a server's own metrics on the same registry.
- Identity is never a metric label. Tenant and workspace belong in logs.

## Logs

One JSON object per line on stdout, with `event`, `level`, `timestamp` (ISO 8601 UTC) and `service`. Inside a request each line also carries the `tenant_id` and `workspace_id` from the edge's identity headers and the active span's `trace_id`.

- `get_logger(__name__)` returns a structured logger: `log.info("note_added", length=12)`.
- Standard library logging is routed through the same renderer, `extra` fields included.
- Request URLs from the `httpx` family are held at `WARNING`, so a key in a query string never reaches a log.
- A logged exception that is, or was caused by, a database error (SQLAlchemy, asyncpg, psycopg) keeps its frames and classes but no message, because Postgres and SQLAlchemy write row values into the message. The line adds `db_error` with the SQLSTATE and the constraint, table and column the driver reported.

## Traces

- The inbound `traceparent` header is honoured.
- Spans export over OTLP to `OTEL_EXPORTER_OTLP_ENDPOINT` when it is set. A recorded database error is exported with its type only: no message and no stacktrace, since a message line can imitate a frame. Its frames are on the log line.
- On a FastMCP app the request span is FastMCP's own; on a FastAPI app it is the FastAPI instrumentation's.
- `inject_trace_headers(headers)` carries the trace onto an outbound call.
- Each response carries `x-correlation-id`: the inbound trace id when there is one.
