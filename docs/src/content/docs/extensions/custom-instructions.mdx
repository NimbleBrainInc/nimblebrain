---
title: Custom Instructions
description: Guidance for one app is a workspace skill bound to its tools.
---

Guidance a workspace wants the agent to follow when it uses one app (house rules for a CRM's stages, a brand voice for a document tool) is a **workspace skill bound to the app's tools**. The host does not read instructions from the app itself.

Create the skill in **This Workspace → Skills**, or with `skills__create`, and give it a `tool-affinity` matching the app's tools:

```yaml
---
name: crm-house-rules
description: How we use the CRM's stages and fields.
loading-strategy: dynamic
tool-affinity:
  - crm__*
---
Move a deal to "Qualified" only after a call is logged.
```

It reaches the agent before its first call to one of those tools, on the same call as the app's own skill, and costs nothing on a turn that never touches the app. For guidance that must hold before the agent picks any tool, make the skill always on instead. See [Skills](/using/skills/) for the format and the tiers.

What an app's author wants every workspace to know is the app's own guidance: its `instructions` and the skills it publishes ([Skills published by an MCP server](/using/skills/#skills-published-by-an-mcp-server)).

The host no longer reads an `app://instructions` resource from apps; a server that still publishes one is not affected, and its text no longer reaches the prompt. Move that text into a workspace skill as above.
